# 轻量化能力系统设计文档（GAS-lite）

> [!NOTE]
> 本文提炼一套与具体项目无关的轻量化能力系统（**GAS-lite**）设计模型，其核心命题是：能力拥有完整的授权—撤销（**Authorize–Revoke**）生命周期，而非“激活即结束”（**Activate-and-End**）的一次性调用；模型在服务器权威（**Server-Authoritative**）与复制（**Replication**）前提下，以状态标签（**State Tag**）声明式规则和严格的输入—逻辑分离（**Input–Logic Separation**）实现基于状态的自动拦截（**Block**）与自动打断（**Cancel**）。

## 概述

本文档描述一套轻量化能力系统（下称“本系统”）的设计模型，来源于一次对既有能力框架的升级实践：将“激活即结束”（**Activate-and-End**）的一次性调用结构，升级为完整的授权—撤销（**Authorize–Revoke**）生命周期：授权与撤销构成两端，持续（**Sustain**）阶段位于其间；并引入状态标签驱动的声明式拦截与打断。

设计目标：

1. **轻量化**：不引入属性集（**Attribute Set**）、游戏效果（**GameplayEffect**）、能力任务（**AbilityTask**）、游戏提示（**GameplayCue**）与预测回滚（**Prediction**）；仅保留行为逻辑与可选的输入绑定能力。
2. **清晰**：输入与逻辑职责分离；状态规则以数据（标签集合）声明，而非在输入层编写条件分支。
3. **可演进**：为后续引入能力规格（**Ability Spec**）级运行时授予与撤销预留兼容路径。

设计原则：

- 服务器权威：一切状态变更在权威端裁决，客户端只读并响应复制。
- 显式优于隐式：规则、顺序、匹配方向均在文档与代码中显式定义。
- 集合语义：状态与规则均以集合（**Set Semantics**）为基础，不引入计数与堆叠。

本文中的类名、方法名与签名为抽象示例，落地时按项目命名规范映射；引擎类型（如 `FGameplayTag`、`FGameplayTagContainer`）为 Unreal Engine 5 的通用类型。

## 一、总体架构

三层结构：

```text
输入层（Input Layer，本地）
  输入动作（InputAction）→ 触发标签；
  相位翻译：按下 → 授权信号；释放 / 中止（仅按住型）→ 触发结束信号

逻辑层（Logic Layer，服务器权威）
  触发管线映射（Trigger Table）：触发标签 → 有序能力管线
  状态容器（State Container）：状态标签集合
  生命周期编排：授权例程 / 撤销流程 / 逐帧回调
  声明式规则：必需 / 禁止 / 拥有 / 打断

复制与表现（Replication & Presentation）
  复制属性 → OnRep → 客户端钩子（Client Hook）
  表现通道：客户端钩子 + 自定义 Multicast RPC
```

数据流：输入相位 → 触发信号（**RPC**）→ 逻辑编排 → 状态变更（复制）→ 客户端钩子。

分离契约（**Contract**）：

| 角色 | 职责 |
|---|---|
| 输入层 | 解释输入相位并翻译为抽象触发信号；不涉及能力逻辑 |
| 逻辑层 | 触发信号 → 生命周期编排与规则判定；不解释输入设备与相位 |
| 能力（行为对象） | 不感知输入：无输入字段、无输入事件、无输入相位 |

## 二、输入—逻辑分离契约

### 2.1 输入相位与按住型声明

- 输入绑定建立于输入层组件，输入映射条目包含：输入动作、触发标签、相位声明。
- 相位语义：
  - `Started`：始终发送授权信号。
  - `Completed` / `Canceled`：仅在按住型（**While-Held**）条目上发送触发结束信号；`Canceled` 表示输入被系统中止，按释放处理。
  - 相位事件的实际触发时机取决于引擎输入系统的触发器（**Trigger**）配置。
- 按住型声明是唯一与输入相关的语义，且只存在于输入层。

### 2.2 触发结束信号与统一契约

- 逻辑层契约：收到某触发结束信号 → 撤销由该触发标签关联的全部持续能力（原因 `TriggerEnded`）。
- 触发关联以精确匹配记录：能力授权时记录其触发标签；程序化授权不记录触发关联，不受触发结束信号影响。
- 非输入源接入：任何外部系统（AI、脚本、游戏代码）调用同一逻辑层 API 表达同一语义，无需经过输入层。

### 2.3 被否决的设计与原因

| 设计 | 否决原因 |
|---|---|
| 在能力上声明"释放即结束"或"输入保持期间活跃"等输入相关字段 | 违反输入—逻辑分离；能力将依赖输入概念 |
| 逐帧上行输入值（绑定 `Triggered`） | 服务器权威模型下产生持续 RPC 负载；逐帧数据可由权威端视图信息获取或由游戏层自建通道 |
| 在能力内等待输入释放（等价于能力任务） | 本系统不引入能力任务；同时会把输入语义带入能力 |

## 三、能力生命周期（Lifecycle）

本模型的核心命题：能力不是“激活即结束”（**Activate-and-End**）的单次调用，而是具备持续时间维度的状态载体；授权（**Authorize**）与撤销（**Revoke**）构成生命周期两端，持续（**Sustain**）阶段位于其间。

### 3.1 策略形态

```cpp
enum class EAbilityPolicy : uint8
{
    Instant,    // 瞬时：授权例程返回后立即结束，不进入授权状态
    Sustained   // 持续：保持授权状态，直至被撤销
};
```

以枚举替代独立的布尔标记，消除非法组合（例如"瞬时 + 释放结束"）。

### 3.2 授予与撤销（Grant / Revoke）

- 授权时**授予**：置授权标记（复制）+ 记录触发标签与执行上下文（瞬态）+ 将拥有标签写入状态容器。
- 撤销时**清理**：清除授权标记 + 撤销拥有标签（多拥有者检查）+ 清空触发标签与上下文。
- 撤销原因枚举（不复制到客户端）：

```cpp
enum class EAbilityEndReason : uint8
{
    Completed,     // 完成：能力自行撤销
    TriggerEnded,  // 触发结束：输入层触发结束信号
    Canceled,      // 被打断：冲突打断或状态打断
    Destroyed      // 销毁：宿主销毁
};
```

### 3.3 授权例程（顺序）

对每个候选能力实例依次执行：

1. 卫语句：能力有效且未授权；已授权的持续能力忽略重复请求（非重入）。
2. 门禁：状态容器须包含全部必需标签，且不得命中任何禁止标签；不通过则记录日志并跳过。
3. 命令式前置检查：能力自定义的检查函数返回 false 则跳过。
4. 冲突打断：按能力的"授权时打断标签"撤销身份标签命中的已授权能力（原因 `Canceled`）；瞬时能力同样执行本步（仅打断他人，自身不进入授权状态）。
5. 仅持续能力：置授权标记、记录触发标签、缓存上下文、授予拥有标签（授予引起的状态变更触发打断扫描）、按需开启逐帧。
6. 执行能力的授权逻辑。
7. 瞬时能力：流程结束，无状态残留；需要写入状态时由能力显式调用状态 API。

集合遍历按实例去重：同一能力实例重复配置于多个命中管线条目时，单次请求仅执行一次。

### 3.4 撤销流程（顺序）

1. 卫语句：能力有效且已授权；否则无操作（幂等）。
2. 清除授权标记（先行置位，保证清理期间的重入安全）。
3. 调用撤销钩子（**OnRevoked**；此时拥有标签尚未撤销，上下文仍可读）。
4. 撤销拥有标签（多拥有者检查）；撤销引起的状态变更广播状态事件，但不触发打断扫描。
5. 清空触发标签与上下文。
6. 若无其它已授权能力，关闭逐帧。

瞬时能力不进入本流程。

### 3.5 规则适用矩阵

| 配置 | 瞬时（Instant） | 持续（Sustained） |
|---|---|---|
| 必需标签 / 禁止标签 | 生效 | 生效 |
| 命令式前置检查 | 生效 | 生效 |
| 授权时打断标签 | 生效（打断他人） | 生效 |
| 拥有标签 | 不生效（不授予） | 生效 |
| 被状态打断标签 | 不生效（不授权，无可打断） | 生效 |
| 逐帧回调 | 不调用 | 逐帧调用 |

### 3.6 逐帧（Sustain）调度

- 逻辑组件逐帧能力默认关闭；首个持续能力授权时开启，最后一个撤销后关闭；仅在权威端调用。
- 逐帧遍历按实例去重。
- 权限边界：客户端副本不开启逐帧。

### 3.7 幂等与非重入

- 已授权能力的重复授权请求：忽略。
- 未授权能力的撤销请求：无操作。
- 状态标签的重复增删：无操作、不广播。
- 同一触发标签的释放 / 中止双事件重复到达：撤销流程幂等，安全。

## 四、状态标签与声明式规则

### 4.1 状态容器

- 复制属性：`FGameplayTagContainer`（触发 `OnRep`）。
- 语义：集合（**Set Semantics**），无计数、无堆叠；堆叠由游戏层实现。
- 权威 API：新增（幂等，新增后执行状态打断扫描）、移除（幂等，不触发打断扫描）、包含查询（层级包含）、容器快照查询。
- 变更事件：签名携带新增标签集与移除标签集；服务器本地变更路径与客户端 `OnRep` 路径均广播。

### 4.2 层级包含（Hierarchy-Aware Containment）判定方向

统一约定：**声明父标签可被子标签满足**；过滤器作为祖先，被匹配标签位于其子树内即命中。

| 判定 | 语义 |
|---|---|
| 门禁 | 状态容器满足全部必需标签；不得命中任一禁止标签 |
| 冲突打断 | 目标能力的身份标签等于过滤器或位于其子树内 |
| 状态打断 | 新增标签等于过滤器或位于其子树内 |
| 程序化撤销 | 目标能力的身份标签等于请求标签或位于其子树内 |
| 触发层匹配 | 触发管线映射的键位于请求标签的子树内 |

该方向约定必须在实现与测试中恒定；方向反转（父/子判定互换）是此类系统最常见的一致性缺陷之一，应以自动化测试固定正反例。

### 4.3 规则集

| 规则 | 语义 |
|---|---|
| 必需标签（**RequiredTags**） | 授权必需：状态容器须包含全部标签 |
| 禁止标签（**BlockedTags**） | 授权禁止：状态容器命中任一标签即拒绝 |
| 拥有标签（**OwnedTags**） | 授权期间写入状态容器，撤销时清除；仅持续能力有效 |
| 授权时打断标签（**CancelAbilitiesWithTag**） | 授权时撤销身份标签命中的已授权能力（原因 `Canceled`） |
| 被状态打断标签（**CanceledByTags**） | 状态容器新增标签命中时撤销自身（原因 `Canceled`） |

设计取舍：

- **不引入**拦截方声明的"授权期间拦截他人（等价于 BlockAbilitiesWithTag）"字段：以"拥有标签 + 对方禁止标签"组合等价表达，减少概念数量。示例：能力 A 持续期间拥有 `State.Carrying`；能力 B 配置禁止标签 `State.Carrying`；A 授权期间 B 的授权请求被自动拒绝。
- 状态打断以"状态容器新增标签"为触发点（本系统无游戏效果通道）；移除标签不触发打断。

### 4.4 打断的两个触发点

1. **授权时（冲突打断）**：某能力授权例程中，按其授权时打断标签撤销其它能力。
2. **状态新增时（状态打断）**：状态容器新增标签后，扫描全部已授权能力，命中被状态打断标签者撤销。

两个触发点均先收集目标集合、再执行撤销，避免遍历中集合变更。

### 4.5 多拥有者标签撤销

- 撤销拥有标签时，对每个标签检查其余已授权能力是否仍拥有该标签；仍有拥有者则保留。
- 不引入引用计数结构，避免并行状态失步；以扫描换取单一数据源。
- 命名空间约束：拥有标签应置于独立状态子命名空间；外部代码不应直接增删与拥有标签同名的状态标签。

### 4.6 可观测性

- 规则命中（门禁拒绝、冲突打断、状态打断）以常规日志级输出，包含能力名、原因与命中标签。
- 生命周期常规流转（授权、持续、撤销、触发信号）以详细日志级输出。
- 目标：在不引入调试面板的前提下，使规则判定可被日志追溯。

## 五、寻址模型（Addressing）

### 5.1 三种寻址

| 寻址 | 方式 | 用途 |
|---|---|---|
| 触发寻址 | 触发标签 → 触发管线映射 | 输入信号与程序化的管线授权 |
| 身份寻址 | 身份标签 → 能力集合（层级匹配） | 程序化授权、撤销、查询 |
| 类寻址 | 类型匹配（子类判定） | 程序化授权的辅助入口 |

程序化授权不记录触发关联，不受触发结束信号影响。

### 5.2 触发表与能力自述标签的取舍

背景澄清：GAS（**Gameplay Ability System**）在输入层同样存在映射配置（输入配置资产 / 输入 ID 绑定），因此"表格形态"并非两者的差异点；实质差异是**寻址键（Addressing Key）位于组件还是能力**。

| 维度 | 组件级映射表 | 能力自述标签（GAS 式） |
|---|---|---|
| 寻址键位置 | 组件默认配置 | 能力资产自身 |
| 编辑期总览 | 集中一表，审计性高 | 分散于各能力 |
| 有序管线 | 支持（数组顺序执行多个能力） | 无显式序列语义 |
| 能力身份 | 缺失：触发键无能力粒度 | 稳定：每个能力一个身份 |
| 状态层寻址 | 不充分 | 充分 |
| 规格级授予/撤销兼容性 | 不兼容（静态表） | 天然兼容 |

本系统采用**混合分层**：

- 触发层保留组件级映射表：保留编辑期单点总览与有序管线语义。
- 状态层采用能力自述身份标签：为打断、撤销、查询提供稳定寻址。
- 程序化入口（按身份标签 / 按类）构建于两层之上。

该分层的前提是生命周期处于**激活级**（**Activation Level**）；若未来引入能力规格级运行时授予与撤销，触发层可进一步收敛为“能力声明触发标签 + 领有集合”。

## 六、复制与客户端钩子

### 6.1 复制面

| 数据 | 性质 | 说明 |
|---|---|---|
| 状态容器 | 复制 | `OnRep` 携带旧值，客户端计算差异并广播 |
| 授权标记 | 复制 | `OnRep` 驱动客户端授权 / 撤销钩子 |
| 执行上下文 | 瞬态 | 仅权威端；客户端不可用 |
| 触发关联 | 瞬态 | 仅权威端；不复制 |
| 撤销原因 | 不复制 | 保持最小复制面；需要时由能力经自定义通道传递 |

### 6.2 客户端钩子

- 逻辑组件：状态标签变更事件（新增 / 移除差异），服务器与客户端路径对称广播。
- 能力：客户端授权钩子与客户端撤销钩子，由授权标记的 `OnRep` 驱动，仅客户端触发。
- 中途加入的客户端：首次复制到达时 `OnRep` 正常触发，据此建立本地表现。
- 表现通道：客户端钩子 + 自定义 Multicast RPC；不引入独立的提示（Cue）系统。

## 七、命名与结构约定

### 7.1 命名

- 跨层共享词根：同一语义在能力、逻辑组件、输入组件、RPC 中保持同一动词族（示例：`Authorize` / `Sustain` / `Revoke`）。
- 前缀分工：`Try` 表示组件入口；`Server` 表示 RPC；`On` 表示事件钩子；`Get` / `Is` 表示查询。
- 避免通用引擎动词（如 `Tick`、`IsActive`）作为领域接口名；接口名应承载领域语义。

### 7.2 状态封装

- 授权标记、触发关联与执行上下文置于私有状态区；对外只读查询。
- 状态写入以少量接缝方法暴露（进入授权、退出授权、清空记录），由逻辑组件在固定流程节点调用；接缝方法保持幂等。
- 不使用友元（**friend**）或公开字段进行跨类状态写入。

### 7.3 组件分区顺序（内部约定）

```text
Parameter（可配置参数）
Event Dispatcher（事件分发器）
State（私有运行时状态）
Constructors
Lifecycle Overrides（引擎生命周期重写）
API（主动行为接口）
SPI（服务提供接口）
RPC（私有网络函数）
Response（复制响应函数）
Callback（绑定回调函数）
Internal Function（内部函数）
```

类别命名与显示名采用统一前缀与中文语义名；空分区不输出。

### 7.4 编码约定要点

- 卫语句先行，尽早返回；避免深层嵌套。
- 幂等与单点入口：状态变更仅经接缝方法，重复调用无副作用。
- 函数体内复杂逻辑以序号（`1) 2) 3)`）分步注释；类与公开接口具备文档注释。
- 注释克制：无装饰性符号、无修改日志式描述。

## 八、工程流程与决策记录

### 8.1 流程链

1. **分类**：将请求分类为可行性验证（**Spike**）、局部变更（**Bounded**）或架构级变更（**Architectural**）；架构级走完整流程。
2. **澄清**：逐项提问确认目标、约束与成功标准（网络模型、范围层级、寻址方案等）。
3. **方案对比**：给出 2–3 个方案与取舍，明确推荐与依据。
4. **设计分节**：按生命周期、状态规则、输入层、复制、用例走查分节呈现并逐节确认。
5. **设计文档（Spec）**：固化设计，作为后续争议的绑定权威；实现与计划均以其为准。
6. **实现计划（Plan）**：拆分为可独立验证的任务，含接口清单、逐步操作与提交点。
7. **执行与台账（Ledger）**：逐任务执行；执行期间的每个裁定（**Ruling**）记录原因与代价；不进行未记录的偏离。
8. **终审（Final Review）**：对整条变更做独立或自审复核；按影响分级处理，小问题记录延后而非顺手修改。

### 8.2 执行纪律要点

- 测试先行适用于可分离的纯逻辑（如判定函数）；引擎内难以自动化部分以构建通过 + 场景清单作为验证关卡。
- 每个任务以"可编译、可运行的独立交付物"为边界；强耦合接口（同一编译单元）不强行拆分。
- 环境限制（无终端、无法构建等）作为裁定入账，并在交付信息中显式声明"未运行验证"，不以推测代替证据。

### 8.3 兼容策略

- **零迁移 / 无历史包袱**：适用于改动范围可控、调用面小、可一次性更新的场景；代价是过渡期内相关资产需同步更新。
- **兼容层**：适用于外部消费方不可控的场景；代价是长期维护双轨命名与桥接代码。
- 该选择应在设计阶段显式裁定，并记录于设计文档与台账。

## 九、非目标（Non-Goals）

- 运行时能力规格（**Ability Spec**）级授予与撤销。
- 本地预测（**Local Prediction**）与客户端逐帧手感通道。
- 属性数值（**Attribute**）、**GameplayEffect**、**AbilityTask**、**GameplayCue**。
- 同一能力多实例与重入；重复授权请求在已授权时忽略。
- 标签堆叠与计数（**Stacking**）。
- 输入 `Triggered` 相位的逐帧上行。
- 撤销原因的复制与客户端可见性。

## 附录 B：设计取舍摘要

| 决策点 | 选择 | 备选 | 依据 | 代价 |
|---|---|---|---|---|
| 网络模型 | 服务器权威 + 复制 | 本地预测 / 客户端手感通道 | 状态一致性优先；逐帧数据可权威端获取 | 客户端表现依赖复制与钩子 |
| 范围层级 | 仅激活级授予 / 撤销 | 规格级运行时授予 / 撤销 | 收敛实现面；规格级有独立兼容路径 | 动态能力集需后续演进 |
| 输入语义归属 | 输入层相位声明 | 能力内声明输入语义 | 输入—逻辑分离 | 输入层配置增多一项 |
| 释放处理 | 触发结束信号 + 逻辑层统一契约 | 逐帧输入上行；能力内等待释放 | 避免持续 RPC 负载与能力任务 | 按住型输入需显式声明 |
| 寻址 | 混合分层（触发表 + 身份标签） | 纯组件映射表；纯能力自述标签 | 总览与有序管线 + 状态层稳定寻址 | 两个标签角色需文档澄清 |
| 拦截声明 | 拥有标签 + 对方禁止标签 | 引入拦截方声明字段 | 概念数量更少，表达力等价 | 需要约定拥有标签命名空间 |
| 标签撤销 | 多拥有者扫描 | 引用计数 | 单一数据源，无并行状态失步 | 撤销时多一次扫描 |
| 状态打断触发点 | 状态新增 | 增删均触发 | 语义明确，避免移除副作用 | 移除标签需游戏层显式处理后续状态 |
| 撤销原因 | 不复制 | 复制到客户端 | 最小复制面 | 客户端需区分原因时自建通道 |
| 命名 | 领域化动词族 + 跨层词根一致 | 通用引擎动词 | 可读性与检索性 | 需团队内约定并保持 |
